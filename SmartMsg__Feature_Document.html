Overview

Smart Messenger is a powerful, enterprise-ready messaging solution built natively on the Salesforce Platform. It seamlessly integrates WhatsApp (via Meta Business API or Twilio) and SMS (via Twilio) communication into Salesforce, enabling businesses to engage with their customers in real time — right from Leads, Contacts, Accounts, or any standard/custom object.

Designed with productivity, compliance, and user experience in mind, Smart Messenger combines modern messaging tools with Salesforce data, optional AI-powered features, and automation to drive faster and smarter conversations.

Key Highlights

  • Two-Way Messaging: Send and receive messages directly within Salesforce — supports SMS, WhatsApp (Meta), and WhatsApp (Twilio) channels.
  • Real-Time Notifications: Get live alerts via platform events through the utility bar for every inbound message.
  • Einstein AI Assistance (UI ready): Reframe, AI Summary, and AI Suggestion options are available in the chat UI; backend integration is configurable per deployment.
  • Media Support: Share images, PDFs, videos, and more with rich preview support.
  • Admin Configuration: Connect Meta (WhatsApp Business) or Twilio (SMS and Twilio WhatsApp) using a secure, permission-based configuration screen.
  • Template Creation: Build and manage WhatsApp templates manually for both Meta and Twilio WhatsApp; template creation UI supports header, body, footer, buttons, and object/field mapping.
  • Conversation Chatbot: Configurable dialogue-based chatbot flows for both Meta WhatsApp and Twilio WhatsApp (Dialogue and Option Dialog records).
  • Workflow Integration: Embed the chat experience into your lead-to-case lifecycle, marketing flows, or service automation.
  • Responsiveness: Mobile-friendly UI with support for Salesforce Console Apps, Utility Bar, and Experience Cloud pages.

1. Configuration

Overview

The Configuration module allows Salesforce administrators to securely set up messaging service provider details for channels: SMS (Twilio), WhatsApp (Meta/Facebook), and WhatsApp (Twilio). This forms the foundation for enabling outbound and inbound messaging functionality in the app.

Key Capabilities

  • Configure and manage connection settings for:
    • Twilio (SMS)
    • Meta WhatsApp Business API
    • Twilio WhatsApp (Twilio Content API and Messages API)
  • Separate configuration blocks for each channel.
  • Role-based access: Only users with the SmartMsg_Admin permission set can modify settings.
  • Encrypted handling of sensitive fields (e.g., Auth Tokens, App Secret).
  • Channel-based dynamic field rendering (e.g., Twilio fields for SMS, Meta fields for WhatsApp, Twilio WhatsApp fields for Twilio WhatsApp).
  • Toggle active/inactive status for each provider.
  • Only one WhatsApp provider (Meta or Twilio WhatsApp) can be active at a time for WhatsApp messaging.
  • Real-time validation and user feedback via toast notifications.

Access Control

Only users assigned the SmartMsg_Admin permission set can access or modify the settings. Unauthorized users will see an error message indicating lack of permission.

User Experience

  • Settings are managed via a Lightning Web Component (providerSettingsConfig) with a modal-based form for each provider.
  • Records are fetched and cached using Apex with @AuraEnabled(cacheable=true) annotation.
  • Real-time field-level validation with visual feedback ensures accurate configuration.
  • Configurations are stored in Custom Settings:
    • SmartMsg__Meta_Configuration__c (WhatsApp Meta)
    • SmartMsg__TwilioConfiguration__c (SMS)
    • SmartMsg__Twilio_Whatsapp__c (Twilio WhatsApp)

2. Chat Application (Smart Messenger)

The Chat Application allows Salesforce users to send and receive real-time messages via WhatsApp (Meta or Twilio) and SMS, directly from any standard or custom record like Leads, Contacts, or Accounts. It supports multimedia messages, templates, optional AI capabilities, conversation chatbot, and more.

Permission-Controlled Access

Only users with the SmartMsg_Admin permission set can access the chat component. If a user lacks this permission, they will be shown a friendly message indicating insufficient access.

Select Communication Channel (SMS / WhatsApp)

  • SMS, WhatsApp (Meta), or WhatsApp (Twilio) can be selected via the channel dropdown at the footer, depending on which providers are configured and active.
  • Once selected, all subsequent messages are sent through the chosen channel.
  • WhatsApp messages support rich capabilities like media, templates, and interactive buttons/lists.

Message Composition & Sending

  • The user types a message in the input box at the bottom.
  • A phone field selector dropdown allows choosing the recipient number field from the record (e.g., MobilePhone, Phone).
  • A Send icon triggers message delivery.
  • Character counter is displayed for SMS (e.g. 500 characters max); WhatsApp has no strict character limit.

Message Scheduling

  • Users can schedule a message for future delivery (clock icon).
  • Choose date and time; once confirmed, the message is saved with a "Scheduled" tag.
  • Scheduled messages are styled with a clock icon and time indicator.
  • Scheduling is supported for both SMS and WhatsApp via backend Apex (e.g. UpdateScheduledWhatsAppMessages, RunEveryMinSchedule).

Attach Media or Documents

  • Users can attach a file or a public URL to WhatsApp messages (Attach icon).
  • Toggle between upload file (.png, .pdf, .mp4, .mp3, etc.) or enter public media URL.
  • Previews are rendered inline in the chat for media files.
  • File chips appear below the message box before sending and can be removed.

Request Location

  • For WhatsApp, a Request Location button is available.
  • Sends a predefined message asking the customer to share their location.
  • When the customer shares location, the message is stored with latitude, longitude, address, and name; the chat displays a map thumbnail and link to view on Google Maps.
  • Useful in logistics, service calls, or delivery workflows.

Message Templates

  • Template icon launches the template picker.
  • Search templates by name; view template name, message body, and channel in a table layout.
  • Click a template to auto-fill it into the message box.
  • Especially useful for WhatsApp's 24-hour session rule.

24-Hour Re-Engagement Handling (WhatsApp)

If the customer has not messaged in the last 24 hours, WhatsApp may restrict freeform messages. The app can detect this and prompt the user to send a pre-approved WhatsApp template instead, ensuring compliance with WhatsApp policy.

Pin / Star Important Messages

  • Hover over a message and use the three-dots menu to: Pin a message — shown in a banner at the top; Star a message — marked with a star icon.
  • Starred and pinned messages help highlight key parts of a conversation. A "Show Starred" filter is available.

Search Messages

More Options > Search Messages enables keyword search. Filters and highlights matching messages in the conversation.

Download Chat Transcript

Available under More Options. Downloads the full conversation history in a readable format for compliance, audits, or hand-offs.

Inline Media Rendering

Messages with media are rendered with previews: Images: thumbnail with click-to-zoom. PDF / MP4 / MP3: appropriate file icons and links. Audio: playable via file link. Fallback icons when the file is not previewable.

Einstein AI Assistant (UI Ready)

The Chat Application includes a toggleable Einstein icon at the bottom with three options in the menu:

  • Reframe: Rewrite the drafted message in a clearer or more professional tone (backend integration configurable).
  • AI Summary: Generate a summary of the conversation (backend integration configurable).
  • AI Suggestion: Recommend next best responses based on the conversation (backend integration configurable).

The UI and menu are implemented; the Apex methods (e.g. FlexTemplate) for Reframe, Summary, and Suggestion can be integrated as needed for your org.

Conversation Chatbot

  • Meta WhatsApp and Twilio WhatsApp support configurable chatbot flows.
  • Flows are driven by SmartMsg__Dialogue__c (message content and type) and SmartMsg__Option_Dialog__c (next step based on user choice).
  • First message or session with one inbound is treated as "Hi"; the bot responds with welcome and language/options. Subsequent choices (e.g. New Customer, Existing Customer, Moving Boxes) drive the dialogue tree.
  • Supports buttons, list pickers, ordered question sequences (e.g. reservation forms), and "Is there anything else?" with Yes/No to loop or end.

Typing Indicator (WhatsApp)

When supported by the channel, a typing signal can be sent to the customer while the user composes a message to simulate human-like interaction.

Real-Time Updates via Platform Events

The chat listens to SmartMsg__Incoming_Message__e platform event. New incoming messages appear instantly without refresh. Keeps agents updated in real time for faster replies.

Delivery & Status Tracking

Messages show Sent, Delivered, Read indicators where provided by the provider. Failed messages are marked with a warning icon and tooltip showing failure reason (e.g. invalid number, 24-hour window expired).

Mobile Responsive Design

The component is mobile-optimized with collapsible menus, icon-based actions, and responsive modals. Layouts for file upload, search, and conversation history are tailored for small screens.

3. Template Creation

The Template Creation module allows users to create, preview, and manage WhatsApp message templates for Meta and Twilio WhatsApp, and to manage template usage for SMS. Templates can be reused across conversations and are required for WhatsApp re-engagement outside the 24-hour window.

WhatsApp Templates (Meta and Twilio)

  • Meta WhatsApp: Templates are created and submitted via the Meta Graph API. The app supports manual creation with header, body, footer, buttons, and example values; templates are stored in SmartMsg__Message_Template__c and synced with Meta (e.g. template ID, status).
  • Twilio WhatsApp: Templates are created using the Twilio Content API. Users can create Content templates and save them to SmartMsg__Message_Template__c; status sync (e.g. Pending/Approved) is supported via TwilioWhatsAppTemplateStatusBatch and scheduler.

Manual Template Creation for WhatsApp (Meta)

  • Template Name: Unique identifier; auto-uppercase formatting can be applied.
  • Language: WhatsApp language code (e.g. en_US).
  • Header Type: TEXT, or IMAGE, VIDEO, DOCUMENT for media headers.
  • Header Text: For TEXT header type.
  • Body: Main message content with variables {{1}}, {{2}}, etc.
  • Footer Text: Optional sign-off or disclaimer.
  • Buttons: Quick Reply (e.g. Yes/No), URL, or Phone Number.
  • Example: Example values for body and header (e.g. for media) for template approval.
  • Real-time validation, auto cleanup on cancel, and live preview panel.

Manual Template Creation for Twilio WhatsApp

Twilio WhatsApp templates are created using the Twilio Content API. The app builds the content payload in the UI, creates the content via the API, submits it for Meta/WhatsApp approval (required for WhatsApp delivery), and saves the template to SmartMsg__Message_Template__c with channel Twilio WhatsApp. Template status (e.g. Pending, Approved, Rejected) is synced with Twilio/Meta via TwilioWhatsAppTemplateStatusBatch and TwilioWhatsAppTemplateStatusScheduler.

Creation and approval flow

  1. User fills Template Name, Object (optional), Body Text, Type, and Options (when applicable).
  2. App builds the Twilio Content API JSON payload (body with {{1}}, {{2}} where merge fields were used; variable descriptions for Meta approval).
  3. POST to Twilio Content API creates the content; response Content SID is stored in WhatsApp_Template_ID__c.
  4. App submits the content for Meta/WhatsApp approval (e.g. ApprovalRequests/whatsapp with template name and category such as MARKETING).
  5. Message_Template__c is inserted with Status__c = Pending (if submission succeeded) or Failed (with Error_Response__c if not).
  6. TwilioWhatsAppTemplateStatusBatch / TwilioWhatsAppTemplateStatusScheduler sync status from Twilio/Meta (e.g. Approved/Rejected) back to Status__c.

Real-time validation (required name, option count, button/option limits) and user feedback via toasts. Object and field pickers (same as Meta) support Insert merge field in the body for dynamic content when sending from a record.

AI-Powered Template Suggestions (UI Ready)

The template creation UI includes an option for Using AI to generate template content. Backend integration (e.g. FlexTemplate.generateTemplateJSON) can be wired so that a user provides intent or description and receives suggested header, body with variables, footer, and button recommendations with fields auto-populated. Multi-language support can be extended in future releases.

Template Editing & Management

  • Edit Existing Templates: Templates can be retrieved from Salesforce and edited. WhatsApp (Meta) templates can typically be edited only within a 24-hour window after creation. The form is auto-filled with saved values. Twilio WhatsApp templates are created in the UI (create flow builds Content API payload, submits for Meta approval, and saves to Message_Template__c); editing of already-approved Twilio content may be subject to provider limits.
  • Save & Cancel: Save persists the template to SmartMsg__Message_Template__c and, for Meta, submits to the provider API; for Twilio WhatsApp, create flow calls the Twilio Content API and submits for Meta/WhatsApp approval. Cancel resets the form and closes the modal.
  • SMS: Template records for SMS (body with merge fields, channel SMS) are used by the chat for sending; creation/editing can be done via the same or a simplified flow depending on configuration.

4. Incoming Message Window (Utility Bar)

The Incoming Message Window is a real-time notification panel integrated into the Salesforce Utility Bar. It allows users to view, manage, and respond to inbound WhatsApp (Meta and Twilio) and SMS messages without leaving their current workspace.

Real-Time Platform Events Listener

  • The component listens to SmartMsg__Incoming_Message__e Platform Event.
  • When a new inbound message is received it: Plays a notification sound (e.g. Web Audio API); Blinks the Utility Bar icon to draw attention; Fetches and displays the message without refresh.

Record Navigation

Clicking the sender's name or message header navigates to the associated Contact, Lead, or Account using NavigationMixin, based on SOSL/lookup by incoming phone number.

Tabs: All & Unread

  • ALL: All inbound messages grouped by sender, sorted by recent activity.
  • UNREAD: Only unread message threads for easy triage.

Search Messages

Search bar to filter by sender name or message body. Live filtering across tabs with pagination preserved.

Message Preview & Media Rendering

Messages grouped by sender with latest message content. Rich preview for images (inline thumbnails), audio (embedded player), video (inline player), and files (e.g. PDF, DOC) with download link and file icon.

Channel Identification

Each message shows an icon for its channel: WhatsApp (Meta or Twilio) or SMS.

Message Actions (per thread)

  • Reply: Opens the full Chat Application prefilled with the record and number.
  • Mark as Read: Clears unread badge, stops blinking, updates unread count (e.g. markAsRead Apex).
  • Delete: Permanently deletes the message with confirmation; server-side deletion via Apex.

Pagination Support

Previous and Next controls for the filtered and grouped message list.

Refresh Capability

Refresh button reloads all messages with animated loading feedback.

Utility Bar Integration

Utility item label can show count, e.g. Incoming Messages (3). Blinking icon indicates new message; stops after Mark as Read or user interaction (Reply/Delete).

Quick Access to Full Chat

Reply or clicking a sender opens the Chat Component inside the utility view with full functionality (templates, media, etc.). A Back button returns to the message list.

Last Sent User Awareness

getLastSentUser Apex method checks if the current user sent the last outbound message to the sender. Utility Bar highlight can stay active when the same user is expected to respond.

Mark All as Read (Per Sender)

When a thread is marked as read, all messages from that sender are updated via Apex (markAsRead).

Permission and Security

Data operations use WITH SECURITY_ENFORCED for FLS and CRUD compliance. Apex classes handle errors and surface feedback via toasts on the UI.
